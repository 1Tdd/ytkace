# Audit e correzioni — 4 novembre 2026

## Post con più immagini

Caso segnalato: https://youtube.com/post/Ugkxl-E2JnvJtYVwWcqHBBE67gxh8WcJ8WqC

La risposta pubblica di YouTube contiene quattro immagini nel `postMultiImageRenderer`. La vecchia raccolta dipendeva dalle viste/caricamenti locali e poteva fermarsi all’immagine corrente. Il numero mostrato non attestava che l’elenco fosse completo.

- Recupero dell’elenco dal documento del singolo post, verificando l’identificativo del post e la corrispondenza con l’immagine corrente. Nessuna apertura del browser.
- Attesa del recupero prima di salvare tutte le immagini e aggiornamento del conteggio nel menu. Un errore non viene più presentato come salvataggio completo di una sola immagine.
- Lettura anche dei componenti ELM già materializzati, dei dati associati e degli elementi del carosello non ancora visibili; ricerca del post d’origine anche quando il visualizzatore usa una finestra distinta.
- Gli URL con ritaglio, come `=s288-c-fcrop64=1,...`, vengono normalizzati dal primo `=`. Prima si tagliava dal secondo, producendo un URL originale errato e identità diverse per le varie risoluzioni.
- Test nativo con una fixture ricavata dal post segnalato: quattro immagini in ordine, avatar escluso, varianti deduplicate, ultima immagine inclusa, fallback a risoluzione maggiore, post diverso rifiutato e documenti incompleti gestiti.

## Importazione e libreria

- L’importazione conserva il file originale e la sua estensione: non elimina più capitoli, sottotitoli o tracce aggiuntive tramite una normalizzazione automatica. Evita anche contenitori Opus/Matroska etichettati come `.m4a`.
- I formati accettati dall’importazione sono gli stessi elencati dalla libreria, inclusi WAV, FLAC, OGG, Opus e MKV. La riproducibilità dipende sempre dai codec supportati dal player iOS; importare non equivale a convertire.
- Copia in un file temporaneo e sostituzione atomica dei sottotitoli. Una copia fallita conserva il file precedente e rimuove gli scarti temporanei.
- Importazioni serializzate, nomi Unicode limitati in byte, nomi nascosti corretti e collisioni controllate anche fra estensioni diverse e file associati.
- Copertine esterne mantenute come file associati senza riscrivere il contenuto multimediale. Supportata anche l’importazione di sole copertine per file già presenti, tramite nome corrispondente.
- Errori di creazione directory, copia di copertine e sottotitoli riportati; nei risultati compare anche il numero di elementi effettivamente importati.
- Rinomina con controllo preventivo dei conflitti e ripristino dei file già spostati se un passaggio fallisce. Non sposta più i sottotitoli quando la rinomina del video non riesce.
- Eliminazione: i file associati vengono rimossi solo dopo l’eliminazione del file principale; gli errori vengono mostrati.

## Finalizzazione download

- Titoli uguali in formati diversi non condividono più per errore copertine, sottotitoli e metadati.
- Errori nel caricamento, incorporamento o sostituzione dei sottotitoli propagati fino all’interfaccia. Il file scaricato viene conservato nella libreria e non viene esportato come risultato completo.
- Se il trasferimento finale alla libreria fallisce, il file completato non viene cancellato insieme alla cartella temporanea. Il percorso viene registrato nel log; rimane un file temporaneo, non una copia permanente garantita dal sistema.
- Le copertine ricevute dalla rete devono essere immagini valide con risposta HTTP riuscita. HTML o risposte di errore non vengono salvati come JPEG.
- La continuazione della preparazione delle copertine per Foto torna sul thread principale; controlli di annullamento prima delle ulteriori scritture.
